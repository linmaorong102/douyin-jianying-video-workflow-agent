# 抖音剪映信息流自动制作 Codex Skill

一个面向 Windows 本地环境的抖音信息流视频制作工作流，使用 Codex 作为执行 Agent，以 n8n 调度任务，以剪映专业版完成文本朗读、标题/字幕预设和音乐装配，并为 whisper.cpp、FFmpeg 与确定性本地脚本预留加速执行路径。

> 当前版本：`v0.3.2-preview`
>
> 兼容模式的流程、参数和验收规则已经完整；加速模式的架构和接口已经定义，但字幕强制对齐、SRT 生成、视频预处理等配套脚本仍在开发。请勿把当前预览版描述为“完全无人值守的一键成片系统”。

`v0.3.0-preview`新增单一批量文档多任务解析、文案与视频精确绑定、逐任务内容哈希、错误隔离、批量文案模板和工作区脚本安全安装器。

`v0.3.1-preview`明确字幕文字颜色为白色，浅粉色只用于目标预设自带的描边。

`v0.3.2-preview`取消字幕描边预设，字幕改为纯白基础样式，无描边、无背景、无阴影和无发光。

## 这个项目解决什么问题

普通的桌面自动化视频制作容易遇到以下问题：

- 每次从空白剪映草稿开始，重复设置画布、标题、字幕和音乐。
- Computer Use 需要频繁截图、识别界面和点击，速度慢且容易受弹窗影响。
- 剪映自动字幕可能出现错字、同音字、漏字和标点变化。
- 视频、配音、字幕、标题和音乐的结束时间不一致。
- 素材不足时没有统一的补片规则，容易出现黑帧、空白或长时间定格。
- n8n 生成了任务，却被误认为已经完成剪映草稿。

本项目把这些要求固化为一个可复用的 Codex Skill，并把工作拆成“任务调度、确定性媒体处理、剪映界面执行、自动验收、视觉验收”五类职责。

## 适用场景

- 用户提供视频素材和口播文案，制作 9:16 抖音信息流视频。
- 使用剪映专业版的“文本朗读”生成固定音色口播。
- 使用固定的剪映标题、字幕预设和背景音乐。
- 要求字幕与原文完全一致，每段字幕只能一行。
- 要求视频、口播、字幕、标题和音乐严格等长。
- 希望使用 n8n 监控素材库和文案目录，并生成可追踪的制作任务。
- 希望减少 Computer Use 的截图和时间线拖动次数。

## 不适用场景

- 无剪映专业版或无 Windows 桌面控制能力的环境。
- 需要完全绕过剪映、只用 FFmpeg 渲染成片的项目。
- 需要自动发布到抖音账号的项目；本 Skill 不包含自动投稿。
- 未经用户授权直接导出或上传成片。
- 需要使用图片补画面、AI生成图片或AI生成视频的工作流。

## 系统组成

```text
用户放入素材与文案
        │
        ▼
n8n：监控、去重、生成 task.json、记录状态
        │
        ▼
Codex Agent：读取 Skill、选择模式、调用工具、处理异常
        │
        ├── Computer Use：操作剪映、生成配音、套预设、加音乐、视觉验收
        ├── whisper.cpp：取得最终口播的语音时间点
        ├── FFmpeg/FFprobe：读取时长、静音、转码、裁剪、拼接
        └── 本地脚本：原文对齐、SRT生成、视频预处理、机器验收
        │
        ▼
可复核的剪映草稿
        │
        ▼
用户明确授权后才允许导出
```

### 组件分工

| 组件 | 作用 | 不负责什么 |
|---|---|---|
| Codex | 决策、调用工具、处理异常、验收 | 不应临时重写重复的精确算法 |
| Skill | 参数、流程、权限、停止条件、验收标准 | 不是独立运行的软件 |
| n8n | 文件监控、任务生成、状态调度 | 不能原生点击剪映 |
| Computer Use | Windows剪映界面操作 | 不适合精确计算字幕与帧级时长 |
| whisper.cpp | 本地语音识别和时间点 | 不设置剪映字幕样式 |
| FFmpeg/FFprobe | 确定性媒体处理 | 不替代剪映标题和字幕预设 |
| 本地脚本 | 对齐、SRT、媒体处理、验收 | 当前预览版尚未全部提供 |

## 两种执行模式

### 兼容模式

当字幕对齐和视频预处理脚本尚未安装时使用。

- n8n 创建任务。
- Codex 使用 Computer Use 操作剪映。
- 剪映生成“解说小帅”口播。
- 剪映生成字幕时间，Codex用原文校正字幕。
- 在剪映中完成画面、标题、字幕、音乐和时长对齐。
- 逐项验收并保存草稿。

优点是组件要求少；缺点是 Computer Use 操作次数较多。

### 加速模式

仅当以下组件全部存在并通过测试时启用：

- n8n素材入库和文案解析工作流。
- FFmpeg与FFprobe。
- whisper.cpp程序和中文模型。
- 经过测试的字幕对齐、SRT生成、视频预处理、结果验收脚本。
- 与当前剪映版本兼容的母版草稿。
- 可用的Computer Use桌面控制。

加速模式流程：

1. n8n生成幂等任务。
2. Computer Use在剪映母版中生成最终口播。
3. 本地程序定位口播文件并读取准确时长。
4. whisper.cpp生成语音时间点。
5. 对齐脚本把时间点映射到原始文案，生成无错字SRT。
6. FFmpeg按口播时长完成静音、转码、裁剪和补片。
7. Computer Use一次性导入预处理视频和SRT。
8. 在剪映中批量应用标题和字幕预设，加入指定音乐。
9. 自动验收文字与时长，Computer Use验收视觉效果。

详细规则见 [`references/accelerated-execution.md`](references/accelerated-execution.md)。

## 默认成片参数

### 画布和声音

- 比例：9:16。
- 分辨率：1080 × 1920。
- 帧率：30fps。
- 口播：剪映文本朗读。
- 音色：解说小帅。
- 语速：1.1x。
- 原视频声音：静音。
- 背景音乐：剪映收藏中的“舒缓 煽情 唯美 浪漫 轻音乐”，作者 Lance。
- 横屏视频：清晰主画面居中，上下使用同一视频的模糊背景，无黑边。

### 标题

- 文字：文案第一段，不改写。
- 字体：得意黑。
- 字号：15。
- 坐标：X=0，Y=854。
- 样式：直接使用用户确认的剪映黄色文字黑色描边预设。
- 时长：从00:00:00持续到口播结束。

### 字幕

- 文字：只来自原始口播文案。
- 字体：得意黑。
- 字号：10。
- 坐标：X=102，Y=-810。
- 文字颜色：白色。
- 样式：剪映基础字幕样式，不使用带描边预设；关闭描边、背景、阴影和发光。
- 每段字幕只能一行。
- 不允许错字、同音字替换、漏字、增字、改写或标点变化。
- 全部字幕顺序连接后必须与任务中的 `narration_text` 完全一致。

### 时长

- 最终口播音频是唯一主时钟。
- 视频、模糊背景、字幕、标题、背景音乐与口播从00:00:00开始。
- 所有轨道结束误差不得超过1帧，30fps下约为0.033秒。
- 视频长于口播时裁剪。
- 视频短缺不超过2秒时可短片段衔接或末帧补齐。
- 视频短缺超过2秒时必须从素材库选择相关片段补齐。
- 不得截断口播、留下黑帧、空白或用长时间定格敷衍。

## 环境要求

### 必需

- Windows 10或Windows 11。
- Codex桌面端或其他能够加载Codex Skill的环境。
- Windows Computer Use能力。
- 剪映专业版，并能使用目标音色、标题/字幕预设和收藏音乐。
- n8n本地版。
- D盘或其他具备足够空间的工作目录。

### 加速模式额外要求

- FFmpeg和FFprobe。
- whisper.cpp及中文模型。
- 本项目后续提供或用户自行实现的确定性辅助脚本。
- 经过当前剪映版本验证的母版草稿和界面配置。

本仓库不分发whisper.cpp二进制程序、Whisper模型、剪映安装程序、付费字体、音乐文件或任何用户素材。

## 安装

### Windows D盘安装方式

从GitHub Releases下载ZIP，解压后确认最终路径为：

```text
D:\codex的skill\douyin-jianying-video-workflow-agent\SKILL.md
```

不要多套一层同名文件夹，例如下面这种路径是错误的：

```text
D:\codex的skill\douyin-jianying-video-workflow-agent\douyin-jianying-video-workflow-agent\SKILL.md
```

安装后重新打开Codex任务，或者开始一个新任务，让Codex重新发现Skill。

若要让n8n实际使用本版本的批量文案功能，还需要把Skill内已经验证的脚本安装到工作区。首次安装或更新时运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\codex的skill\douyin-jianying-video-workflow-agent\scripts\install-workspace.ps1" -WorkspaceRoot "D:\抖音信息视频工作流" -Force
```

安装器会在覆盖旧脚本前创建带时间戳的备份，并把批量文案模板复制到工作区的`文案模板`目录。它不会删除素材、文案、任务、剪映草稿或成片。

### 其他系统

将整个仓库复制到当前Codex配置的skills目录。目录名必须保持：

```text
douyin-jianying-video-workflow-agent
```

## 默认工作区

默认工作区为：

```text
D:\抖音信息视频工作流
```

建议目录：

```text
01_待入库        新放入的原始视频
02_素材库        已登记素材与视频素材库.json
03_口播文案      标题和正文文件
04_制作任务      TASK-*目录和task.json
05_剪映草稿      草稿映射与交付信息
06_成片          用户授权后导出的文件
scripts          n8n调用的本地脚本
workflows        可导入n8n的工作流JSON
tools            whisper.cpp等本地工具
```

如果使用其他根目录，需要同时修改n8n工作流、任务脚本和Skill中的目录配置，不能只修改其中一处。

## 文案格式

推荐只维护一个 `03_口播文案\批量视频文案.txt`，每条任务用分隔符包裹：

```text
【任务开始】
视频：一镜到底.mp4
标题：这是第一条视频标题
正文：这是第一条视频的完整口播文案。
【任务结束】

【任务开始】
视频：一镜到底 (2).mp4
标题：这是第二条视频标题
正文：这是第二条视频的完整口播文案。
【任务结束】
```

以后只在文件末尾追加新任务块。解析脚本为每个任务块分别计算哈希；追加新任务不会重复创建旧任务。某一块缺少视频、标题或正文时只记录该块错误，不影响其他有效任务。删除总文档中的旧块不会删除已经生成的任务，修改旧块会生成新的任务版本。

仍兼容一个文件只写一条任务的格式。批量模式必须填写完整的 `视频：文件名和扩展名`；单任务模式可以通过文案与视频同名自动匹配。

## 使用方式

将视频和文案放入约定目录后，可以向Codex发送：

```text
使用 $douyin-jianying-video-workflow-agent 处理下一条视频任务，先完成剪映草稿，不要导出。
```

也可以指定任务：

```text
使用 $douyin-jianying-video-workflow-agent 读取 TASK-20260820-001，检查组件并选择加速模式或兼容模式，完成草稿后逐项报告验收结果。
```

## n8n职责

- 监控素材和文案目录。
- 计算源文件哈希，防止重复任务。
- 生成独立 `TASK-*` 目录与 `task.json`。
- 调度已经存在且通过测试的本地脚本。
- 记录任务阶段、产物路径和失败原因。
- 保留手动触发入口。

推荐状态：

```text
等待处理
→ 配音已生成
→ 字幕已生成
→ 视频已处理
→ 等待剪映装配
→ 草稿已完成
→ 等待人工确认
```

n8n不能仅凭节点执行成功就把任务标记为“剪映草稿已完成”。

## Computer Use提速原则

- 固定剪映版本、窗口大小、系统缩放和面板布局。
- 一次观察界面后，批量执行同一稳定面板内的点击和输入。
- 只在阶段开始、界面变化、出现弹窗、用户打断或阶段完成时重新截图。
- 标题和字幕必须使用剪映预设并批量应用。
- 剪映更新、预设变化、弹窗遮挡或坐标失效时停止，不得盲点。
- Computer Use只承担必须在剪映中完成的工作，不承担帧级计算。

## 完成标准

只有以下检查全部通过，才能报告“剪映草稿已完成”：

- 标题与文案一致，预设、字体、字号、坐标和时长正确。
- 字幕预设、字体、字号和坐标正确，每段严格一行。
- 字幕全文与 `narration_text` 完全一致。
- 画布比例正确，横屏主画面清晰居中，上下模糊背景无黑边。
- 口播音色和速度正确，原视频静音，背景音乐正确。
- 视频、模糊背景、标题、字幕、口播和音乐结束误差不超过1帧。
- 视频短缺超过2秒时已使用相关补充片段。
- 草稿保存到约定目录，源素材和原始文案没有被删除或覆盖。

任何一项失败，都必须报告失败项和修正需求，不能把失败描述为完成。

## 权限边界

- 创建任务不等于完成草稿。
- 完成草稿不等于允许导出。
- 只有用户明确要求导出，或任务中存在 `export.approved: true`，才允许输出到 `06_成片`。
- 本项目不包含自动发布到抖音、代表用户留言、账号登录或购买付费素材的权限。

## 隐私和安全

公开仓库和提交记录中禁止包含：

- 用户视频、照片、口播文案和客户信息。
- 剪映草稿、缓存和导出成片。
- n8n凭据、Webhook密钥、API密钥、Cookie、OAuth令牌和密码。
- Whisper模型、剪映音乐文件、付费字体或无权分发的素材。
- 包含联系方式、医疗信息、未成年人信息或其他敏感内容的截图。

如果凭据曾经进入Git历史，仅从最新版本删除文件是不够的；应立即撤销凭据并清理历史。

## 已知限制

- 剪映界面更新可能使坐标或预设网格失效。
- “解说小帅”音色和收藏音乐依赖剪映账号与地区可用性。
- 当前预览版尚未包含完整的字幕强制对齐和FFmpeg预处理脚本。
- 无法可靠定位剪映生成的口播音频时，加速模式必须停止或回退兼容模式。
- 自动选补充素材无法确认内容相关性时，需要Codex或用户选择。
- Skill能提高一致性，但不能保证第三方软件界面永远不变化。
